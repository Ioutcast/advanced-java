# Как запросить самую популярную строку запроса?

## Постановка задачи

Поисковая система будет записывать все строки запроса, используемые пользователями для каждого поиска, в файлах журналов. Длина каждой строки запроса не должна превышать 255 байт.

Предположим, что на данный момент имеется 10 миллионов записей (степень повторения этих строк запроса относительно высока. Хотя общее количество составляет 10 миллионов, если убрать повторы, это число не превысит 3 миллионов). Пожалуйста, посчитайте 10 самых популярных строк запроса. Требуемый объем памяти не может превышать 1 ГБ. (Чем чаще повторяется строка запроса, тем больше пользователей запрашивают ее и тем она популярнее.)

## Подход к решению

Максимальная длина каждой строки запроса составляет 255 байт, а для 10 миллионов строк требуется примерно 2,55 ГБ памяти. Поэтому мы не можем прочитать все строки в памяти для обработки.

### Способ 1: Разделяй и властвуй

Разделяй и властвуй по-прежнему остается очень практичным методом.

Разделите его на несколько небольших файлов, чтобы строки из одного небольшого файла можно было напрямую загрузить в память для обработки, а затем найдите 10 наиболее часто встречающихся строк в каждом файле; наконец, используйте небольшую кучу для подсчета 10 наиболее часто встречающихся строк во всех файлах.

Этот метод возможен, но не лучший. Вот другие методы.

### Способ 2: метод HashMap

Хотя общее количество строк относительно велико, после дедупликации оно не превышает 300 Вт. Поэтому вы можете рассмотреть возможность сохранения всех строк и времени их появления в HashMap. Занимаемое пространство составляет 300w\*(255+4)≈777M (где 4 представляет собой 4 байта, занимаемые целым числом). Видно, что 1 Гб памяти вполне достаточно.

**Идея заключается в следующем**:

Сначала пройдите по строке. Если его нет на карте, сохраните его непосредственно на карте, а значение запишется как 1; если он есть на карте, добавьте 1 к соответствующему значению. Временная сложность этого шага составляет `O(N)`.

Затем пройдите по карте, чтобы построить небольшую верхнюю кучу из 10 элементов. Если количество вхождений пройденной строки больше, чем количество вхождений строки в верхней части кучи, замените ее и настройте кучу на небольшую верхнюю кучу.

После завершения обхода 10 строк в куче — это строки, которые появляются чаще всего. Временная сложность этого шага составляет `O(Nlog10)`.

### Способ 3: метод префиксного дерева

Метод 2 использует HashMap для подсчета количества раз. Если эти строки имеют большое количество одинаковых префиксов, вы можете рассмотреть возможность использования дерева префиксов для подсчета количества вхождений строки. В узлах дерева хранится количество вхождений строки, а 0 означает отсутствие вхождений.

**Идея заключается в следующем**:

При перемещении по строке ищите в дереве префиксов. Если найдено, добавьте 1 к количеству строк, хранящихся в узле. В противном случае создайте новый узел для этой строки. После завершения построения установите количество вхождений строки в листовом узле равным 1.

Наконец, небольшая верхняя куча по-прежнему используется для сортировки количества вхождений строки.

## Резюме

Деревья префиксов часто используются для подсчета вхождений строк. Еще одно его широкое применение — поиск строк, определение наличия повторяющихся строк и т. д.
