# Как осуществлять управление сервисами на базе Dubbo

## Вопрос на собеседовании

Как выполнить управление службами, резервную службу службы, повторную попытку при сбое и повторную попытку по истечении времени на основе дубло?

## Что хочет знать интервьюер

Управление сервисами. Если я задам вам этот вопрос, то на самом деле я хочу посмотреть, есть ли у вас представление об управлении сервисами**, потому что это проблема, с которой обязательно столкнутся люди, которые создавали сложные микросервисы.

**Резервный сервис**. Это необходимая тема, когда речь идет о сложных распределенных системах, поскольку распределенные системы вызывают друг друга взад и вперед. Если какая-либо система выйдет из строя, если вы не отступите, рухнет ли все? Это было бы слишком обманом.

**Повторить попытку в случае сбоя**. В распределенных системах сетевые запросы настолько часты, что если из-за проблем с сетью произойдет случайный сбой, нужно ли пытаться еще раз?

**Повторная попытка по истечении времени**. То же, что и выше. Если сеть случайно стала работать медленнее и время ожидания истекло, как я могу повторить попытку?

### Резервный сервис

Например, если служба A вызывает службу B, а служба B зависает, служба A попытается вызвать службу B несколько раз, но если она по-прежнему не работает, то она напрямую откатится, будет использовать логику резервного копирования и вернет ответ пользователю.

Например, у нас есть интерфейс `HelloService`. `HelloServiceImpl` имеет конкретную реализацию этого интерфейса.

```java
public interface HelloService {
   void sayHello();
}

public class HelloServiceImpl implements HelloService {
    public void sayHello() {
        System.out.println("hello world......");
    }
}
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:dubbo="http://code.alibabatech.com/schema/dubbo"
    xsi:schemaLocation="http://www.springframework.org/schema/beans        http://www.springframework.org/schema/beans/spring-beans.xsd        http://code.alibabatech.com/schema/dubbo        http://code.alibabatech.com/schema/dubbo/dubbo.xsd">

    <dubbo:application name="dubbo-provider" />
    <dubbo:registry address="zookeeper://127.0.0.1:2181" />
    <dubbo:protocol name="dubbo" port="20880" />
    <dubbo:service interface="com.zhss.service.HelloService" ref="helloServiceImpl" timeout="10000" />
    <bean id="helloServiceImpl" class="com.zhss.service.HelloServiceImpl" />

</beans>

<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns:dubbo="http://code.alibabatech.com/schema/dubbo"
    xsi:schemaLocation="http://www.springframework.org/schema/beans        http://www.springframework.org/schema/beans/spring-beans.xsd        http://code.alibabatech.com/schema/dubbo        http://code.alibabatech.com/schema/dubbo/dubbo.xsd">

    <dubbo:application name="dubbo-consumer"  />

    <dubbo:registry address="zookeeper://127.0.0.1:2181" />

    <dubbo:reference id="fooService" interface="com.test.service.FooService"  timeout="10000" check="false" mock="return null">
    </dubbo:reference>

</beans>

```

Если нам не удается вызвать интерфейс, мы можем равномерно вернуть значение null через `mock`.

Значение Mock также можно изменить на true, и тогда класс Mock можно будет реализовать по тому же пути, что и интерфейс. Правило именования — «имя интерфейса + суффикс `Mock`». Затем реализуйте собственную резервную логику в классе Mock.

```java
public class HelloServiceMock implements HelloService {
    public void sayHello() {
        // 降级逻辑
    }
}
```

### Повторная попытка с ошибкой и повторная попытка по истечении времени ожидания

Так называемая повторная попытка при сбое означает, что если потребителю не удается вызвать поставщика, например, генерируется исключение, в это время должна быть возможность повторить попытку или ее можно повторить, если время вызова истекло. Конфигурация следующая:

```xml
<dubbo:reference id="xxxx" interface="xx" check="true" async="false" retries="3" timeout="2000"/>
```

Дай мне каштан.

Интерфейс определенного сервиса занимает 5 секунд. Ты не можешь ждать здесь. После того, как вы настроили здесь тайм-аут, я подождал 2 секунды, но он не вернулся. Я просто отстранился. Я не могу дождаться тебя.

Вы можете объяснить, как вы устанавливаете эти параметры, исходя из конкретных сценариев вашей компании:

- `timeout`: Обычно установлено значение `200ms`, мы думаем, что оно не может превышать `200ms` и еще не вернулось.
- `retries`: установите повторные попытки, обычно при отправке запроса на чтение. Например, если вы хотите запросить часть данных, вы можете установить повторные попытки. Если он не будет прочитан с первого раза, будет сообщено об ошибке, и будет предпринято указанное количество повторных попыток, чтобы попытаться прочитать еще раз.
