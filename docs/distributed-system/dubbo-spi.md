## Анализ вопросов на собеседовании

### Что такое спи?

Проще говоря, Spi — это `service provider interface`. Грубо говоря, что это значит? Например, если у вас есть интерфейс, и теперь этот интерфейс имеет 3 класса реализации, какой класс реализации следует выбрать для этого интерфейса при работе системы? Для этого требуется спи. Вам необходимо найти соответствующий класс реализации и загрузить его в соответствии с указанной конфигурацией или конфигурацией по умолчанию, а затем использовать объект экземпляра этого класса реализации.

Дай мне каштан.

У вас есть интерфейс A. A1/A2/A3 — это разные реализации интерфейса A соответственно. Если вы настроите `接口 A = 实现 A2`, то, когда система фактически работает, ваша конфигурация будет загружена и будет создан экземпляр объекта с использованием A2 для предоставления услуг.

Где обычно используется механизм spi? **Сценарий расширения плагина**. Например, если вы разрабатываете платформу с открытым исходным кодом для использования другими, если вы хотите, чтобы другие написали плагин и вставили его в вашу среду с открытым исходным кодом для расширения определенной функции, тогда вступает в действие идея spi.

###Воплощение идей Java spi

Классическая идея spi обычно используется всеми, например, jdbc.

Java определяет набор интерфейсов jdbc, но Java не предоставляет класс реализации jdbc.

Но когда проект фактически запущен, какие классы реализации интерфейса jdbc следует использовать? Вообще говоря, мы должны **в соответствии с используемой нами базой данных**, например mysql, вы должны ввести `mysql-jdbc-connector.jar`; оракул, ты представишь `oracle-jdbc-connector.jar`.

Если во время работы системы она встретит интерфейс, который вы используете jdbc, она будет использовать класс реализации, указанный в jar-файле, который вы представили внизу.

### мысли даббо

Dubbo также использует идею spi, но не использует механизм spi jdk. Это набор spi-механизмов, реализованных самостоятельно.

```java
Protocol protocol = ExtensionLoader.getExtensionLoader(Protocol.class).getAdaptiveExtension();
```

Интерфейс протокола: когда система работает, dubbo определит, какой класс реализации этого интерфейса протокола следует использовать для создания экземпляра объекта для использования.

Он найдет настроенный вами протокол, загрузит настроенный вами класс реализации протокола в jvm, а затем создаст экземпляр объекта, просто используйте свой класс реализации протокола.

Приведенная выше строка кода широко используется в даббо, то есть для многих компонентов резервируется один интерфейс и несколько реализаций, а затем динамически находится соответствующий класс реализации согласно конфигурации при работе системы. Если вы не настраиваете его, просто используйте реализацию по умолчанию, без проблем.

```java
@SPI("dubbo")
public interface Protocol {

    int getDefaultPort();

    @Adaptive
    <T> Exporter<T> export(Invoker<T> invoker) throws RpcException;

    @Adaptive
    <T> Invoker<T> refer(Class<T> type, URL url) throws RpcException;

    void destroy();

}
```

В банке Даббо, в файле `/META_INF/dubbo/internal/com.alibaba.dubbo.rpc.Protocol`:

```xml
dubbo=com.alibaba.dubbo.rpc.protocol.dubbo.DubboProtocol
http=com.alibaba.dubbo.rpc.protocol.http.HttpProtocol
hessian=com.alibaba.dubbo.rpc.protocol.hessian.HessianProtocol
```

Итак, вот как механизм spi в dubbo работает по умолчанию. На самом деле это интерфейс протокола. `@SPI("dubbo")` означает, что класс реализации предоставляется через механизм SPI. Класс реализации находится в файле конфигурации, используя dubbo в качестве ключа по умолчанию. Имя файла конфигурации совпадает с полным именем интерфейса. Класс реализации по умолчанию можно найти через dubbo по ключу: `com.alibaba.dubbo.rpc.protocol.dubbo.DubboProtocol`.

Если вы хотите динамически заменить класс реализации по умолчанию, вам необходимо использовать интерфейс `@Adaptive`. В интерфейсе протокола два метода помечены `@Adaptive`, что означает, что эти два интерфейса будут реализованы прокси.

Что это значит?

Например, этот интерфейс протокола имеет два метода, отмеченных аннотациями `@Adaptive`. При запуске для протокола будет создан прокси-класс. В двух методах этого прокси-класса будет прокси-код. Прокси-код будет динамически получать ключ в соответствии с протоколом, указанным в URL-адресе во время выполнения. По умолчанию — даббо. Вы также можете указать это самостоятельно. Если вы укажете другие ключи, будут получены экземпляры других классов реализации.

### Как самостоятельно расширить компоненты в даббо

Поговорим о том, как расширить компоненты в даббо самостоятельно.

Напишите проект самостоятельно. Если его можно упаковать в пакет jar, создайте `META-INF/services` в каталоге `src/main/resources`, поместите в него файл с именем: `com.alibaba.dubbo.rpc.Protocol` и создайте в нем `my=com.bingo.MyProtocol`. Перенесите банку на частный сервер Nexus самостоятельно.

Затем самостоятельно создайте проект `dubbo provider`, основанный на созданном вами jar-файле, а затем задайте конфигурацию в файле конфигурации Spring:

```xml
<dubbo:protocol name=”my” port=”20000” />
```

Когда провайдер запустится, он будет загружен в строку конфигурации `my=com.bingo.MyProtocol` в нашем jar-пакете, а затем определенный вами MyProtocol будет использоваться в соответствии с вашей конфигурацией. Это краткое объяснение. Вы можете заменить большое количество компонентов внутри dubbo с помощью описанного выше метода, просто добавьте свой собственный jar-пакет и затем настройте его.

![dubbo-spi](./images/dubbo-spi.png)

Dubbo предоставляет большое количество точек расширения, подобных описанным выше. То есть, если вы хотите что-то расширить, вам нужно только написать jar самостоятельно, позволить вашему проекту потребителя или поставщика зависеть от вашего jar и настроить файл, соответствующий имени интерфейса, в указанном каталоге вашего jar, который проходит `key=实现类`.

Затем для соответствующих компонентов, аналогично `<dubbo:protocol>`, используйте класс реализации, соответствующий вашему ключу, для реализации интерфейса. Вы можете самостоятельно расширить различные функции dubbo и предоставить свою собственную реализацию.
