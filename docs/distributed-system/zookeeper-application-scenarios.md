### Распределенная координация

На самом деле это очень классическое использование Zookeeper. Проще говоря, это похоже на то, что ваша система A отправляет запрос в mq, а затем система B обрабатывает сообщение после его использования. Откуда система А знает результаты обработки системы Б? Zookeeper можно использовать для координации между распределенными системами. После того, как система А отправит запрос, она может зарегистрировать прослушиватель значения определенного узла в Zookeeper. Как только система B завершит обработку, она может изменить значение этого узла в Zookeeper. Система А получит уведомление немедленно, что является идеальным решением.

### распределенная блокировка

Дай мне каштан. Для определенных данных непрерывно выполняются две операции модификации, и две машины получают запрос одновременно, но только одна машина может завершить выполнение другой машины перед ее выполнением. Тогда вы можете использовать распределенную блокировку Zookeeper в это время. После получения запроса машина сначала получает распределенную блокировку Zookeeper, то есть может создать znode, а затем выполнить операцию; затем другая машина также пытается создать znode, но обнаруживает, что не может его создать, поскольку он был создан кем-то другим. Он может только дождаться, пока первая машина завершит выполнение, а затем выполнить его.

### Управление метаданными/конфигурационной информацией

Zookeeper можно использовать для управления информацией о конфигурации многих систем. Например, многие распределенные системы, такие как Kafka и Storm, будут использовать Zookeeper для управления некоторыми метаданными и информацией о конфигурации. Разве центр регистрации даббо не поддерживает Zookeeper?

![zookeeper-meta-data-manage](./images/zookeeper-meta-data-manage.png)

### Высокая доступность высокой доступности

Это должно быть очень распространено. Например, многие системы больших данных, такие как Hadoop, HDFS, Yarn и т. д., предпочитают разрабатывать механизмы высокой доступности высокой доступности на основе Zookeeper. То есть важный процесс обычно имеет два основных и резервный процесса. Если основной процесс зависнет, он немедленно переключится на резервный процесс через Zookeeper.
