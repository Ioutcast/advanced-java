#Введение в поисковую систему

## Прошлая и настоящая жизнь Lucene и ES

Lucene — самая продвинутая и мощная доступная библиотека поиска. Если вы разрабатываете непосредственно на основе Lucene, это очень сложно. Даже если вы пишете несколько простых функций, вам все равно придется написать много Java-кода, и вам необходимо глубоко понимать принципы.

ElasticSearch основан на Lucene, скрывает сложность Lucene и предоставляет простой и удобный в использовании API-интерфейс RESTful / Java API (также существуют API-интерфейсы на других языках).

- Механизм распределенного хранения документов.
- Распределенная поисковая система и система анализа.
- Распределенный, поддерживающий данные уровня PB

## Основные концепции ES

### Почти в реальном времени

Почти в реальном времени имеет два значения:

- Существует небольшая задержка (около 1 с) с момента записи данных до момента, когда данные могут быть найдены.
- Поиск и анализ на основе ЭП можно выполнить за считанные секунды

### Кластерный кластер

Кластер содержит несколько узлов, и к какому кластеру принадлежит каждый узел, определяется конфигурацией. Для приложений малого и среднего размера в начале кластера обычно имеется только один узел.

### Узел узла

Узел — это узел в кластере, а также узел имеет имя, которое по умолчанию назначается случайным образом. Узел по умолчанию присоединится к кластеру с именем `elasticsearch`. Если вы запустите несколько узлов напрямую, они автоматически сформируют кластер elasticsearch. Конечно, один узел также может образовывать кластер эластичного поиска.

### Документ и поле

Документ — это наименьшая единица данных в ES. Документ может представлять собой часть данных о клиенте, часть данных классификации продуктов, часть данных заказа и обычно представляется структурой данных json. Каждый тип под индексом может хранить несколько документов. В документе имеется несколько полей, и каждое поле является полем данных.

```json
{
    "product_id": "1",
    "product_name": "iPhone X",
    "product_desc": "苹果手机",
    "category_id": "2",
    "category_name": "电子产品"
}
```

### Индекс

Индекс содержит набор данных документа со схожей структурой, например индекс продукта. Индекс содержит множество документов и представляет собой тип похожих или идентичных документов.

### Тип

Тип: каждый индекс может иметь один или несколько типов. Тип — это логическая классификация индекса. Например, в индексе продукта есть несколько типов: тип химической продукции ежедневного использования, тип электротехнической продукции и тип свежей продукции. Поля документа каждого типа могут быть разными.

### осколок

Одна машина не может хранить большой объем данных. ES может разделить данные в индексе на несколько сегментов и распределить их для хранения на нескольких серверах. С помощью сегментов вы можете расширяться по горизонтали, хранить больше данных и распределять такие операции, как поиск и анализ, на несколько серверов для выполнения, повышая пропускную способность и производительность. Каждый осколок представляет собой люценовый индекс.

### реплика

Любой сервер может выйти из строя в любой момент, и в этом случае сегмент может быть потерян, поэтому для каждого сегмента можно создать несколько реплик. Реплика может предоставлять услуги резервного копирования, когда сегмент не может гарантировать, что данные не будут потеряны. Несколько реплик также могут повысить пропускную способность и производительность операций поиска. Первичный сегмент (устанавливается один раз при создании индекса, не может быть изменен, по умолчанию — 5), сегмент реплики (количество может быть изменено в любое время, по умолчанию — 1), значение по умолчанию — 10 сегментов на индекс, 5 основных сегментов, 5 сегментов реплик, минимальная конфигурация высокой доступности — 2 сервера.

Скажем так, шарды делятся на первичные и реплики. Первичный осколок обычно называют шардом, а осколок-реплику обычно называют репликой.
