# Проблема конкуренции параллелизма в Redis

## Вопрос на собеседовании

В чем проблема конкуренции параллелизма в Redis? Как решить эту проблему? Знаете ли вы решение CAS для транзакций Redis?

## Что хочет знать интервьюер

Это также очень распространенная проблема в Интернете, когда несколько клиентов одновременно пишут ключ. Данные, которые должны были поступить первыми, могут поступить позже, что приведет к неправильной версии данных; или несколько клиентов одновременно получают ключ, изменяют значение и затем записывают его обратно. Пока порядок неправильный, данные будут неверными.

А у самого Redis есть CAS-подобное решение оптимистической блокировки, которое естественным образом решает эту проблему.

## Анализ вопросов на собеседовании

В определенный момент несколько экземпляров системы обновляют определенный ключ. Распределенная блокировка может быть реализована на базе Zookeeper. Каждая система получает распределенную блокировку через Zookeeper, чтобы гарантировать, что только один экземпляр системы может одновременно работать с определенным ключом, а другим не разрешено чтение или запись.

![zookeeper-distributed-lock](./images/zookeeper-distributed-lock.png)

Данные, которые вы хотите записать в кеш, должны быть получены из MySQL и записаны в MySQL. При записи в MySQL необходимо сохранить временную метку. Когда он извлекается из MySQL, также определяется временная метка.

Каждый раз перед записью сначала определите, является ли временная метка текущего значения новее временной метки значения в кэше. Если да, то его можно записать, в противном случае он не сможет перезаписать новые данные старыми.
