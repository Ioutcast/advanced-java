#Углубимся во внутренние принципы исполнения Hystrix

Ранее мы узнали о самой базовой технологии Hystrix, поддерживающей высокую доступность: **изоляция ресурсов** + **ограничение скорости**.

-Создать команду;
- Выполните эту команду;
— Настройте группу и пул потоков, соответствующие этой команде.

Здесь мы хотим поговорить о базовом процессе выполнения, шагах и принципах Hystrix после того, как вы начнете выполнять эту команду и вызовете метод выполнения() этой команды.

В процессе объяснения этого процесса я расскажу о некоторых других основных и важных функциях Hystrix.

Вот блок-схема всех 8 шагов, и я подробно объясню каждый шаг. Я считаю, что в процессе обучения идея станет более ясной, если обратиться к этой блок-схеме.

## Шаг 1: Создайте команду

Объект HystrixCommand или HystrixObservableCommand представляет запрос или вызов зависимой службы. При создании вы можете передать в конструктор любые необходимые параметры.

- HystrixCommand в основном используется для вызовов, которые возвращают только результат.
— HystrixObservableCommand в основном используется для вызовов, которые могут возвращать несколько результатов.

```java
// 创建 HystrixCommand
HystrixCommand hystrixCommand = new HystrixCommand(arg1, arg2);

// 创建 HystrixObservableCommand
HystrixObservableCommand hystrixObservableCommand = new HystrixObservableCommand(arg1, arg2);
```

## Шаг 2: Вызов метода выполнения команды

Выполнение команды инициирует вызов зависимой службы.

Для выполнения команды вы можете выбрать один из четырех методов: выполнение(), очередь(), наблюдение(), toObservable().

Методы выполнения() и очереди() доступны только для HystrixCommand.

- выполнить(): блокировать сразу после вызова. Это синхронный вызов до тех пор, пока зависимая служба не вернет ни одного результата или не выдаст исключение.
- очередь(): возвращает Future, который является асинхронным вызовом. Позже вы сможете получить единственный результат через Будущее.
- Observe(): подписаться на объект Observable. Observable представляет результат, возвращаемый зависимой службой, и получает копию объекта Observable, представляющего результат.
- toObservable(): возвращает объект Observable. Если мы подпишемся на этот объект, команда будет выполнена и будет получен возвращаемый результат.

```java
K             value    = hystrixCommand.execute();
Future<K>     fValue   = hystrixCommand.queue();
Observable<K> oValue   = hystrixObservableCommand.observe();
Observable<K> toOValue = hystrixObservableCommand.toObservable();
```

Execute() на самом деле вызовет метод очереди().get(), вы можете взглянуть на исходный код Hystrix.

```java
public R execute() {
    try {
        return queue().get();
    } catch (Exception e) {
        throw Exceptions.sneakyThrow(decomposeException(e));
    }
}
```

В методе очереди() будет вызван toObservable().toBlocking().toFuture().

```java
final Future<R> delegate = toObservable().toBlocking().toFuture();
```

То есть сначала получите объект Future через toObservable(), а затем вызовите метод get() Future. Таким образом, на самом деле, независимо от того, каким образом выполняется команда, в конечном итоге ее выполнение зависит от toObservable().

## Шаг 3. Проверьте, включено ли кеширование (используется нечасто)

Начиная с этого шага, мы познакомимся с основным принципом работы Hystrix и рассмотрим некоторые из наиболее продвинутых функций и возможностей Hystrix.

Если эта команда включает кэш запроса и результат этого вызова существует в кеше, результат будет возвращен непосредственно из кеша. В противном случае перейдите к следующим шагам.

## Шаг 4. Проверьте, включен ли автоматический выключатель

Проверьте, включен ли автоматический выключатель у зависимой службы, соответствующей этой команде. Если автоматический выключатель разомкнут, Hystrix не выполнит эту команду, а напрямую запустит механизм возврата и вернет результат возврата.

## Шаг 5. Проверьте, заполнен ли пул потоков/очередь/семафор

Если пул и очередь командного потока заполнены или семафор семафора заполнен, команда не будет выполнена, но механизм отката будет вызван напрямую, и информация об отклонении будет отправлена на автоматический выключатель для статистики.

## Шаг 6: Выполните команду

Вызовите методstruct() объекта HystrixObservableCommand или метод run() объекта HystrixCommand, чтобы фактически выполнить эту команду.

- HystrixCommand.run() возвращает один результат или выдает исключение.

```java
// 通过command执行，获取最新一条商品数据
ProductInfo productInfo = getProductInfoCommand.execute();
```

— HystrixObservableCommand.construct() возвращает объект Observable, который может получить несколько результатов.

```java
Observable<ProductInfo> observable = getProductInfosCommand.observe();

// 订阅获取多条结果
observable.subscribe(new Observer<ProductInfo>() {
    @Override
    public void onCompleted() {
        System.out.println("获取完了所有的商品数据");
    }

    @Override
    public void onError(Throwable e) {
        e.printStackTrace();
    }

    /**
     * 获取完一条数据，就回调一次这个方法
     *
     * @param productInfo 商品信息
     */
    @Override
    public void onNext(ProductInfo productInfo) {
        System.out.println(productInfo);
    }
});
```

Если используется метод пула потоков, а время выполнения HystrixCommand.run() или HystrixObservableCommand.construct() превышает время ожидания, то поток, в котором находится команда, выдаст исключение TimeoutException, и будет выполнен резервный механизм возврата, независимо от значения, возвращаемого run() илиstruct(). В другом случае, если выполнение команды завершится неудачей и выдаст другие исключения, также будет использоваться резервный вариант. В обоих случаях Hystrix отправит события исключений на автоматический выключатель для получения статистики.

**Обратите внимание**: мы не можем завершить поток, который вызывает зависимую службу с серьезной задержкой. Мы можем только выдать вам исключение TimeoutException.

Если тайм-аут отсутствует и выполнение нормальное, вызывающий поток получит некоторые результаты, полученные путем вызова зависимого сервиса, а затем Hystrix также выполнит некоторые записи журнала и статистику измерения показателей.

## Шаг 7: Проверка работоспособности разрыва цепи

Hystrix отправит автоматическим выключателям информацию об успехе, сбое, отклонении, тайм-ауте и других событиях каждого зависимого сервисного вызова. Автоматический выключатель подсчитает количество этих событий и решит, следует ли срабатывать автоматический выключатель, исходя из доли аномальных событий. Если автоматический выключатель включен, он будет отключен напрямую в следующий период времени, и будет возвращен резервный результат.

Если позже автоматический выключатель попытается выполнить команду, и вызов не ошибется и вернет нормальные результаты, то Hystrix отключит автоматический выключатель.

## Шаг 8: Вызов резервного механизма возврата

В следующих ситуациях Hystrix вызовет резервный механизм возврата.

- Автоматический выключатель разомкнут;
- Пул потоков/очередь/семафор заполнен;
- таймаут выполнения команды;
- run() илиstruct() выдают исключение.

Как правило, в резервном механизме рекомендуется указывать некоторые возвращаемые значения по умолчанию, например некоторую логику статического кода, или извлекать некоторые данные из кэша в памяти. Постарайтесь больше не делать здесь сетевых запросов.

В качестве резервного варианта, если необходимо выполнить сетевой вызов, этот вызов также следует поместить в HystrixCommand для изоляции.

— В HystrixCommand реализован метод getFallback(), обеспечивающий резервный механизм.
— В HystrixObservableCommand реализуйте метод summaryWithFallback() и возвращайте объект Observable, который может предоставить резервные результаты.

Если резервный вариант не реализован или резервный вариант выдает исключение, Hystrix вернет Observable, но не вернет никаких данных.

Различные методы выполнения команд имеют разные результаты возврата, если резервный вариант пуст или ненормален.

- Для выполнения() вызовите исключение напрямую.
- Для очереди() возвращает Future и выдает исключение при вызове get().
— Для Observe() возвращается объект Observable, но когда метод subscribe() вызывается для подписки на него, немедленно вызывается метод onError() вызывающего объекта.
— Для toObservable() возвращается объект Observable, но когда для подписки на него вызывается метод subscribe(), немедленно вызывается метод onError() вызывающей стороны.

## Различные методы выполнения

— выполнить(), получить Future.get(), а затем получить один результат.
- очередь(), возвращает будущее.
— Observe(), немедленно подпишитесь на Observable, затем запустите 8 основных шагов выполнения, верните копию Observable и сразу же перезвоните вам результат при подписке.
- toObservable() возвращает исходный Observable, на который необходимо вручную подписаться для выполнения 8 основных шагов.
